## 1. О проекте

### Что такое Ventra CRM?

Ventra CRM — это веб-приложение для управления продажами и клиентами. CRM расшифровывается как «Customer Relationship Management» — система управления отношениями с клиентами.

Простыми словами: это инструмент, который помогает небольшим командам не терять клиентов, следить за сделками и общаться с покупателями прямо из одного окна.

### Какие задачи решает проект?

- **Единый входящий ящик** — все сообщения от клиентов (Telegram, email) собираются в одном месте. Не нужно переключаться между разными приложениями.
- **Клиентская база** — хранение информации о клиентах: контакты, история общения, заметки.
- **Воронка сделок** — отслеживание этапов продажи: от первого контакта до закрытия сделки.
- **Задачи** — создание и назначение задач, привязанных к конкретным клиентам и сделкам.
- **AI-подсказки** — встроенный искусственный интеллект анализирует входящие сообщения и сам предлагает: создать задачу, записать клиента, передвинуть сделку на следующий этап.
- **Telegram-интеграция** — переписка с клиентами прямо через бота в Telegram, в реальном времени.
- **Аналитика** — графики и статистика по продажам и активности команды.

### Основные разделы приложения

| Раздел | Что делает |
|---|---|
| `/inbox` | Единый входящий ящик (Telegram + email) |
| `/clients` | Список и карточки клиентов |
| `/pipeline` | Воронка продаж (канбан-доска) |
| `/tasks` | Список задач |
| `/projects` | Управление проектами |
| `/analytics` | Аналитика и отчёты |
| `/assistant` | AI-ассистент |
| `/settings` | Настройки, интеграции, подключение Telegram |
| `/team` | Управление командой |

## 2. Что нужно установить

Ниже перечислено всё, что нужно установить перед началом работы. Устанавливай в том порядке, в котором написано.

---

### Visual Studio Code

**Что это такое?**
Visual Studio Code (VS Code) — это редактор кода. Именно в нём ты будешь писать и читать код проекта. Это самый популярный редактор среди веб-разработчиков.

**Зачем нужен?**
Без него очень сложно работать с кодом: не будет подсветки синтаксиса, подсказок, поиска по файлам и многого другого.

**Где скачать?**
[https://code.visualstudio.com](https://code.visualstudio.com)

**Как установить?**
1. Перейди по ссылке выше.
2. Нажми большую синюю кнопку «Download» — сайт сам определит твою операционную систему.
3. Запусти скачанный файл и следуй инструкциям установщика (просто нажимай «Далее»).

**Как проверить, что всё установилось правильно?**
Найди VS Code в списке приложений и открой его. Должно появиться окно редактора с приветственной страницей.

**Рекомендуемые расширения:**
После установки VS Code добавь эти расширения — они сильно упрощают работу:
- **ESLint** — показывает ошибки в коде прямо в редакторе
- **Tailwind CSS IntelliSense** — подсказки для стилей
- **Prettier** — автоматически форматирует код

Чтобы установить расширение: нажми иконку «Extensions» в левой панели VS Code (или `Ctrl+Shift+X`), введи название расширения в поиске и нажми «Install».

### Node.js

**Что это такое?**
Node.js — это среда, которая позволяет запускать JavaScript-код не в браузере, а прямо на компьютере. Без неё проект вообще не запустится.

**Зачем нужен?**
Весь проект написан на JavaScript и TypeScript. Node.js нужен, чтобы запускать сервер и собирать проект.

> ⚠️ **Важно:** Ventra использует специальную встроенную базу данных, которая работает только в **Node.js версии 22** и выше. Более старые версии не подойдут.

**Где скачать?**
[https://nodejs.org](https://nodejs.org)

**Как установить?**
1. Зайди на сайт nodejs.org.
2. Выбери версию **22 или выше** (на странице она может быть помечена как «Current» или «LTS» — подойдёт любая при условии что версия 22+).
3. Скачай установщик для своей системы (Windows `.msi`, macOS `.pkg`).
4. Запусти файл и следуй инструкциям.

**Как проверить, что всё установилось правильно?**
Открой терминал (на Windows — «Командная строка» или «PowerShell», на macOS — «Terminal») и выполни:

```bash
node --version
```

Должно вывестись `v22.x.x` или выше. Если версия ниже 22 — удали Node.js и установи заново нужную версию.

Также проверь npm (это менеджер пакетов, устанавливается вместе с Node.js):

```bash
npm --version
```

Должно вывестись что-то вроде `10.x.x`.

### Git

**Что это такое?**
Git — это система контроля версий. Она отслеживает все изменения в коде и позволяет нескольким людям работать над одним проектом одновременно без конфликтов.

**Зачем нужен?**
Без Git невозможно скачать проект с GitHub, сохранять изменения и отправлять их в общий репозиторий.

**Где скачать?**
[https://git-scm.com](https://git-scm.com)

**Как установить?**

*На Windows:*
1. Перейди на [git-scm.com](https://git-scm.com) и нажми «Download».
2. Запусти установщик. На вопросах установщика можно оставить всё по умолчанию и просто нажимать «Next».
3. На шаге «Choosing the default editor» выбери «Use Visual Studio Code as Git's default editor».

*На macOS:*
Открой «Terminal» и выполни:
```bash
git --version
```
Если Git не установлен, macOS сама предложит установить инструменты разработчика — согласись.

**Как проверить, что всё установилось правильно?**
В терминале выполни:

```bash
git --version
```

Должно вывестись `git version 2.x.x` или выше.

После установки Git нужно один раз настроить имя и email — Git будет добавлять их к твоим коммитам (сохранениям):

```bash
git config --global user.name "Твоё имя"
git config --global user.email "твой@email.com"
```

### ngrok

**Что это такое?**
ngrok — это программа, которая создаёт временный публичный адрес в интернете, ведущий на твой локальный компьютер. Это нужно для того, чтобы Telegram мог отправлять сообщения на твой локальный сервер.

**Зачем нужен?**
Telegram не может отправить сообщение на `localhost:3000`, потому что этот адрес доступен только тебе. ngrok создаёт промежуточный туннель — Telegram отправляет сообщения на публичный адрес ngrok, а тот передаёт их на твой компьютер.

> Нужен только если ты будешь тестировать Telegram-интеграцию. Для общей разработки интерфейса ngrok не требуется.

**Где скачать?**
[https://ngrok.com](https://ngrok.com)

**Как установить?**
1. Зарегистрируйся на сайте ngrok.
2. Скачай версию для своей платформы.
3. После скачивания запусти команду аутентификации из личного кабинета ngrok (выглядит примерно так: `ngrok config add-authtoken ТВОЙ_ТОКЕН`).

**Как проверить, что всё установилось правильно?**
В терминале выполни:

```bash
ngrok --version
```

Должно вывестись версия программы.

## 3. Создание аккаунтов

GitHub — это платформа для хранения кода и совместной работы. Весь код Ventra хранится на GitHub.

**Зачем нужен:** Позволяет использовать Claude как AI-напарника при разработке. Claude читает код проекта и помогает писать новые функции, находить ошибки и разбираться в чужом коде.

## 4. Получение доступа к проекту

Код Ventra хранится в закрытом репозитории на GitHub. Чтобы получить к нему доступ, нужно пройти три шага.

### Шаг 1 — Тимлид добавляет тебя в репозиторий

Сообщи тимлиду своё имя пользователя GitHub (то, которое ты указал при регистрации). Тимлид зайдёт в настройки репозитория и добавит тебя как коллаборатора (collaborator).

### Шаг 2 — Ты принимаешь приглашение

GitHub пришлёт письмо на твой email — найди его и нажми «Accept invitation». Либо зайди на [github.com/notifications](https://github.com/notifications) — там будет уведомление.

### Шаг 3 — Проверь доступ

1. Перейди на страницу репозитория — тимлид пришлёт тебе ссылку.
2. Ты должен видеть список файлов проекта. Если видишь — доступ получен.
3. Если страница показывает «404 Not Found» — попроси тимлида перепроверить приглашение.

## 5. Скачивание проекта

«Скачать проект» в мире разработки называется «клонировать репозиторий». Клонирование создаёт копию всего кода на твоём компьютере. Выбери один из двух способов.

---

### Через GitHub Desktop

Этот способ проще — всё делается через интерфейс программы.

1. Открой **GitHub Desktop**.
2. В меню сверху выбери **File → Clone repository**.
3. Перейди на вкладку **GitHub.com**.
4. В списке репозиториев найди `ai-crm` (или поищи в поиске). Если не видишь — убедись, что вошёл в правильный аккаунт GitHub.
5. В поле **Local Path** выбери, куда сохранить проект. Лучше создать отдельную папку, например `C:\Projects\` на Windows или `~/Projects/` на macOS.
6. Нажми **Clone**.

GitHub Desktop скачает весь проект и откроет его. Готово!

---

### Через терминал

Этот способ для тех, кто предпочитает командную строку.

**Что такое git clone?**
`git clone` — это команда, которая скачивает весь проект с GitHub на твой компьютер.

**Как выбрать папку?**
В терминале нужно сначала перейти в папку, куда хочешь сохранить проект, а потом выполнить клонирование.

```bash
# Перейди в нужную папку (пример для macOS/Linux):
cd ~/Projects

# Или для Windows:
cd C:\Projects

# Скачай проект (вставь реальную ссылку репозитория):
git clone https://github.com/твоя-организация/ai-crm.git

# Перейди в папку проекта:
cd ai-crm
```

Ссылку на репозиторий возьми на GitHub: открой страницу репозитория, нажми зелёную кнопку **Code** и скопируй HTTPS-адрес.

После выполнения команд в папке `ai-crm` появятся все файлы проекта.

## 6. Как открыть проект

Проект нужно открыть в двух программах: VS Code и Claude Desktop. Это разные инструменты — VS Code для написания кода, Claude для помощи с кодом.

> ⚠️ **Важно:** Всегда открывай **корневую папку проекта** — папку `ai-crm`. Не нужно открывать `src`, `components` или любую другую вложенную папку. Если открыть не ту папку, ни VS Code, ни Claude не увидят всего проекта — они не смогут понять его структуру и правильно работать.

---

### Visual Studio Code

1. Открой VS Code.
2. В меню сверху выбери **File → Open Folder** (или нажми `Ctrl+K, Ctrl+O` на Windows, `Cmd+K, Cmd+O` на macOS).
3. В диалоге выбери папку `ai-crm`.
4. Нажми **Open** (или **Выбор папки**).

Слева появится дерево файлов — ты увидишь все папки и файлы проекта.

---

### Claude Desktop

1. Открой Claude Desktop.
2. Нажми кнопку **Open Folder** (иконка папки рядом с полем ввода).
3. Выбери ту же корневую папку `ai-crm`.
4. Claude подключится к проекту и начнёт понимать его структуру.

После подключения Claude будет видеть все файлы проекта и сможет давать конкретные советы по коду, а не общие ответы.

## 7. Первый запуск проекта

Запуск происходит через терминал. Если ты используешь VS Code, удобно открыть встроенный терминал прямо в редакторе: **Terminal → New Terminal** (или `` Ctrl+` ``).

### Шаг 1 — Перейди в папку проекта

Если ты открыл терминал через VS Code — он уже находится в нужной папке. Если открыл отдельно — перейди в папку проекта:

```bash
cd путь/к/папке/ai-crm
```

### Шаг 2 — Установи зависимости

```bash
npm install
```

**Что делает эта команда?**
Она читает файл `package.json` (список всех библиотек, которые нужны проекту) и скачивает все эти библиотеки в папку `node_modules`. Это может занять 30–60 секунд.

> Никогда не удаляй папку `node_modules` руками — её всегда можно восстановить командой `npm install`.

### Шаг 3 — Запусти сервер разработки

```bash
npm run dev
```

### Как выглядит успешный запуск?

В терминале должно появиться примерно следующее:

```
   ▲ Next.js 16.x.x
   - Local:        http://localhost:3000
   - Network:      http://192.168.x.x:3000

 ✓ Starting...
 ✓ Ready in 2.3s
```

Если ты видишь слово **Ready** и адрес `http://localhost:3000` — сервер запустился успешно.

### Шаг 4 — Открой приложение в браузере

Открой любой браузер и перейди по адресу:

```
http://localhost:3000
```

Должна открыться страница входа Ventra CRM. Используй тестовые данные для входа:

- **Email:** `demo@nexuscrm.io`
- **Пароль:** `demo1234`

Если страница открылась и ты вошёл — поздравляем, проект работает!

### Как остановить сервер?

Вернись в терминал и нажми `Ctrl+C`. Сервер остановится.

## 8. Структура проекта

Вот как организован код проекта. Здесь описано только самое важное — то, что тебе нужно знать в первую очередь.

```
ai-crm/
├── src/                    ← Весь основной код приложения
│   ├── app/                ← Страницы и API (Next.js App Router)
│   │   ├── (app)/          ← Страницы для авторизованных пользователей
│   │   │   ├── inbox/      ← Страница входящих сообщений
```

## 9. Как работать с Git

Git сохраняет историю изменений кода. Вот базовый процесс, который повторяется каждый день.

### Ежедневный рабочий процесс

**1. В начале рабочего дня — скачай последние изменения**

```bash
git pull
```

Эта команда скачивает всё, что другие разработчики добавили с момента твоей последней работы. Делай это каждый раз перед тем, как начать что-то писать — иначе рискуешь работать с устаревшим кодом.

**2. Пиши код**

Делай свою работу — добавляй функции, исправляй баги.

**3. Посмотри, что изменилось**

```bash
git status
```

Эта команда показывает список файлов, которые ты изменил. Зелёным — то, что готово к сохранению, красным — то, что ещё не добавлено.

**4. Добавь изменения к сохранению**

```bash
git add .
```

Точка означает «добавить все изменённые файлы». Если хочешь добавить только один конкретный файл:

```bash
git add src/app/(app)/clients/page.tsx
```

**5. Сохрани изменения с описанием**

```bash
git commit -m "feat: добавил фильтр по статусу в список клиентов"
```

Коммит — это снимок кода в определённый момент. Описание (после `-m`) объясняет, что именно ты сделал. Пиши описание кратко и понятно.

Используй стандартные префиксы:
- `feat:` — новая функция
- `fix:` — исправление ошибки
- `refactor:` — улучшение кода без изменения поведения
- `chore:` — техническое обслуживание (обновление зависимостей и т. п.)

**6. Отправь изменения на GitHub**

```bash
git push
```

Только после этой команды твои изменения появятся на GitHub и станут доступны остальной команде.

## 10. Работа с ветками

### Почему нельзя работать в main?

Ветка `main` — это основная версия кода, которая считается рабочей и стабильной. Если все будут вносить изменения напрямую в `main`, любая ошибка сразу сломает проект для всей команды.

Вместо этого каждый разработчик создаёт свою отдельную ветку — отдельную копию кода. В ней можно спокойно экспериментировать, и это никак не повлияет на других.

### Как создать новую ветку?

```bash
git checkout -b feat/название-функции
```

Например:

```bash
git checkout -b feat/client-filter
git checkout -b fix/inbox-scroll-bug
git checkout -b refactor/task-modal
```

Эта команда создаёт ветку и сразу переключается на неё.

### Как называть ветку?

Используй формат: `тип/краткое-описание-через-дефисы`

- `feat/telegram-reconnect` — новая функция
- `fix/unread-counter` — исправление бага
- `refactor/conv-row` — рефакторинг компонента

Не используй пробелы и кириллицу в названии ветки.

### Как отправить ветку на GitHub?

В первый раз:

```bash
git push -u origin feat/client-filter
```

После этого — просто `git push`.

### Что такое Pull Request?

Pull Request (PR) — это запрос на слияние твоей ветки с основной `main`. Через PR команда проверяет твой код перед тем, как он попадёт в общую версию.

**Как создать PR:**
1. Открой GitHub и перейди в репозиторий.
2. GitHub сам предложит «Compare & pull request» когда ты отправишь ветку.
3. Нажми эту кнопку, напиши описание того, что сделал, и нажми «Create pull request».
4. Тимлид или коллега проверит код и одобрит его (или попросит исправить).

## 11. Работа с Claude или Codex

AI-инструменты вроде Claude или GitHub Copilot/Codex помогают писать код быстрее. Но чтобы они действительно помогали, а не вредили, соблюдай несколько правил.

### Как правильно работать с AI в этом проекте

**Сначала открой проект**
Перед тем как что-то просить у Claude, убедись, что ты открыл папку проекта (см. раздел 6). Без этого Claude будет давать общие ответы вместо конкретных.

**Сначала читай существующий код**
Прежде чем писать что-то новое, посмотри, как похожее уже сделано в проекте. Например, если хочешь добавить новую модальное окно — сначала посмотри на `TaskModal` или другие существующие модальные окна. Копируй стиль, а не изобретай заново.

**Не меняй архитектуру без необходимости**
Если что-то работает — не трогай. «Переписать это лучше» — опасная идея без обсуждения с командой.

**Используй существующие компоненты**
В `src/components/` есть готовые элементы интерфейса. Попроси Claude найти подходящий компонент перед тем, как создавать новый.

**Не дублируй код**
Если видишь, что пишешь одно и то же в двух местах — это сигнал вынести в отдельную функцию или компонент.

**Следуй стилю проекта**
TypeScript строгий, ESLint настроен. Пиши код так, как он уже написан вокруг тебя.

### Рекомендуемый промпт для Claude

Перед началом работы над задачей используй этот промпт:

> «Сначала внимательно изучи существующую архитектуру проекта. Используй существующие компоненты и утилиты. Не переписывай уже работающий код без необходимости. Следуй текущему стилю проекта. После выполнения убедись, что TypeScript и ESLint проходят без ошибок.»

После этого описывай задачу. Claude сначала изучит проект, а потом предложит решение в рамках уже принятых в нём паттернов.

### Проверяй результат AI

AI иногда ошибается. После того как Claude или Copilot написал код:

1. Прочитай его сам — понимаешь ли, что он делает?
2. Запусти `npm run lint` — нет ли ESLint-ошибок?
3. Запусти `npx tsc --noEmit` — нет ли TypeScript-ошибок?
4. Протестируй в браузере — работает ли так, как ожидалось?

Никогда не отправляй код на GitHub не проверив его лично.

## 12. Правила команды

Эти правила помогают всем работать слаженно и не мешать друг другу.

**Не работай одновременно над одной функцией**
Перед тем как начать — уточни у команды, не работает ли кто-то над тем же самым. Это поможет избежать конфликтов при слиянии кода.

**В начале каждой сессии делай git pull**
Всегда начинай работу с актуальной версии кода.

**После завершения работы делай git push**
Не держи изменения только у себя. Даже незавершённая работа должна быть отправлена на GitHub (в своей ветке, а не в main).

**Перед изменением общих компонентов — согласуй с командой**
Компоненты в `src/components/` используются везде в проекте. Если хочешь изменить один из них — сначала обсуди это с командой, потому что твоё изменение повлияет на всех.

**Проверяй проект перед отправкой на GitHub**
Перед тем как создавать Pull Request, выполни:

```bash
npm run lint        # проверка стиля кода
npx tsc --noEmit   # проверка типов TypeScript
```

Оба должны завершиться без ошибок. Если есть ошибки — исправь их до создания PR.

**Пиши понятные описания коммитов и PR**
«Исправил баг» — плохое описание. «fix: исправил сброс счётчика непрочитанных при выборе другого чата» — хорошее.

## 14. Частые ошибки

### Node.js неправильной версии

**Симптом:**
```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module 'node:sqlite'
```

**Причина:** Установлена версия Node.js ниже 22. Модуль `node:sqlite` существует только начиная с Node 22.

**Решение:** Удали текущую версию Node.js и установи версию 22 или выше. Проверь: `node --version` должно показать `v22.x.x`.

---

### npm install не запускается или выдаёт ошибку

**Симптом:** Ошибка при выполнении `npm install`, команда не распознаётся.

**Причина:** Node.js не установлен или установлен неправильно.

**Решение:**
1. Проверь: `node --version`. Если не работает — переустанови Node.js.
2. Если Node.js установлен, но `npm` не работает — перезапусти терминал.
3. На Windows убедись, что открыл терминал от имени администратора.

---

### localhost:3000 не открывается

**Симптом:** Браузер показывает «Сайт недоступен» или «ERR_CONNECTION_REFUSED».

**Причина:** Сервер разработки не запущен.

**Решение:**
1. Убедись, что выполнил `npm run dev` и видишь сообщение «Ready».
2. Если сервер запущен, но не работает — попробуй перейти на `http://127.0.0.1:3000` вместо `localhost`.
3. Проверь, не занят ли порт 3000 другим приложением. Если занят, останови то приложение или измени порт командой `npm run dev -- -p 3001`.

---

### Telegram сообщения не приходят в Inbox

**Симптом:** Отправляешь сообщение боту в Telegram, но оно не появляется в Ventra.

**Причина:** Webhook не зарегистрирован или ngrok не запущен.

**Решение (по шагам):**
1. Убедись, что запущен ngrok: `ngrok http 3000`. Должен показать публичный адрес `https://xxxx.ngrok-free.app`.
2. Убедись, что запущен dev-сервер: `npm run dev`.
3. Зайди в Ventra → **Settings → Integrations → Telegram** и нажми **Register Webhook** снова.
4. Каждый раз при перезапуске ngrok адрес меняется — нужно заново регистрировать webhook.

---

### Git не видит репозиторий / нет доступа

**Симптом:** Команда `git push` или `git pull` выдаёт ошибку «Repository not found» или «Permission denied».

**Причина:** GitHub не авторизован на твоём компьютере, или ты не получил доступ к репозиторию.

**Решение:**
1. Проверь, что вошёл в правильный аккаунт GitHub в GitHub Desktop.
2. Убедись, что тимлид добавил тебя в репозиторий и ты принял приглашение.
3. Если используешь терминал с HTTPS-адресом: при первом `git push` Git запросит логин и пароль GitHub. Пароль — это **Personal Access Token**, не обычный пароль. Создай его на [github.com/settings/tokens](https://github.com/settings/tokens).

---

### Claude не видит проект

**Симптом:** Claude даёт общие ответы про Next.js вместо конкретных советов по коду.

**Причина:** Папка проекта не открыта в Claude Desktop.

**Решение:**
1. В Claude Desktop нажми кнопку **Open Folder**.
2. Выбери корневую папку `ai-crm` (не `src`, не `components` — именно `ai-crm`).
3. После подключения папки попробуй спросить у Claude: «Покажи структуру проекта» — он должен перечислить реальные файлы.

---

### Ошибки TypeScript

**Симптом:** В терминале или VS Code появляются красные подчёркивания, `npx tsc --noEmit` выдаёт ошибки.

**Причина:** Код не соответствует описанным типам данных.

**Решение:**
1. Прочитай сообщение об ошибке — TypeScript обычно точно указывает файл и строку.
2. Попроси Claude объяснить ошибку: скопируй текст ошибки и вставь в Claude.
3. Не используй `any` для «заглушки» ошибки — это плохая практика. Исправь ошибку правильно.
4. Все TypeScript-ошибки должны быть исправлены перед отправкой кода на GitHub.

---

### Ошибки ESLint

**Симптом:** `npm run lint` выводит предупреждения или ошибки.

**Причина:** Код не соответствует правилам оформления, принятым в проекте.

**Частые причины:**
- Неиспользуемые переменные или импорты (удали их)
- `useEffect` с пропущенными зависимостями (добавь нужные в массив `[]`)
- `let` вместо `const` там, где переменная не меняется

**Решение:** Прочитай сообщение ESLint — в нём написано правило и строка. Исправь и снова запусти `npm run lint`. Все ошибки ESLint должны быть исправлены перед отправкой кода.
